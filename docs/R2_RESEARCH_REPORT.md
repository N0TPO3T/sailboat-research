## 结论

**本轮完成了候选简化与四轮开发，但新场景没有支持“保留安全能力并改善3/5km效率”的主要假设。** 冻结主方案 Forward、原样 R1、简单 Relay 和 RouteCost 消融均为63/72安全到达。相同总数掩盖了不同失败：Forward 相对 R1 新增3个成功，也新增3个失败，不能宣布安全等效。

Forward 与 R1 的60个共同成功场景中，航时平均增加90.68秒，配对中位数增加1秒；3km和5km分别平均增加224.48和49.11秒。开发集的长程收益没有转移至新实例。主方案没有事后更名或再调参。可复用成果是一个更小的候选搜索实现及其失败边界，**不是已验证的提效算法**。不建议据此替换 R1 为默认方案；保留冻结 Forward 作为研究配置和简单对照。

## 冻结方法

Forward的“前向”指A*路线首段方向，不是船艏朝向。输入是当前位置、船艏向、当前目标、终点、静态地图和物理时钟；主方案的选择只使用当前可见状态及规划/切换计时；继承的历史缓存不参与评分（history_gain=0）。低层真实历史与因果重编码保持原样。输出为世界坐标中的下一目标建议，在t+1应用。

候选包括有效旧目标、可见路线顶点/终点，以及沿路线首段方向的一个500m径向点。并非所有目标都距船500m；必要短转角仍存在。地图距离评分为本船到候选的长度，加候选到可见路线后缀的最短连接长度。总代价为地图距离 + 15×船艏转角绝对值(rad) + 0.04×改点距离(m)；最后一项仅在旧目标有效时计算。无风项、历史项或在线预测。

继承参数：额外规划留量上限80m，并受起点/终点可用余量减5m限制；膨胀地图无路时回退原安全地图。一般每10秒规划，非紧急情况至少保持20秒，改点评分改善必须严格超过15。旧目标非终点且距离≤40m、距离>550m或航段失效时进入urgent分支；近障弦余量检查也可触发urgent。这些都是经验规则，80m不是轨迹误差界。

```text
固定低层先根据当前目标 q_t 产生 a_t
                │
可见当前状态 → 高层筛选/评分 → 建议 q'
                │
         物理环境执行已有 a_t
                ↓
         到达 t+1 后应用 q'
                ↓
       用真实过去进行因果历史重编码
```

该示意只说明原有时序，不是新增模块或安全证明。RouteCost使用相同候选和保持规则，只删除转角/改点两项代价；它仍有评分。Relay才是不优化候选分数的对照：在有留量的路线上选可见500m前视点，以开发确定的100m接力距离和80m几何触发参数持有/更新目标。


简短伪代码：保留仍可用旧目标 → 按当前可用空间膨胀地图并规划 → 生成路线顶点/终点/单个前向径向候选 → 当前planned规划地图筛选（通常含附加留量；无路回退时为原安全地图） → 评分 → 按紧急、保持和改善阈值决定建议 → 原协议下一秒应用。详见src/sailboat_routing/r2_planner.py:35–96及121起Relay实现。

## 有具体证据的机制与限制

**角度不是普遍无用。** s271_030_staggered_slow_5000在t=915具有完全相同决策输入。窄候选的−15°目标总代价3409.436，纯前向目标3421.023；分别于t=916应用，t=917首次产生物理差异。纯前向最终多38秒，安全结局相同。证据：`forward_angle_same_state_t915.json`与`forward_vs_narrow_execution.json`。

**预警不等于有效改点。** 第二轮predict20共1568次预测触发，其中1043次当前位置余量已低于40m；731次触发对应实际目标改变。外推线段包含起点，因此own<40时即使船正在远离障碍，也会触发。不能直接把整体收益归因于历史信息。其相对原relay100新增4成功/1失败，但26个共同成功的航时均值+41.5秒、中位差0秒。证据：`round2/decision_mechanisms.csv`、`round2_prediction_selection.json`。

**改点代价与改点阈值可能同时抑制必要接力。** 新开发场s371_009_channel_fast_1000在t=210输入完全相同。新目标的地图成本从577.961降至561.150，减少16.812m；原改点代价17.566使综合改善仅1.104，未达到15阈值。路线成本版本在t=211改点，485秒安全到达；原前向版本359秒缓冲侵入。固定状态复算中，单独去掉改点代价的改善18.670可触发，单独去掉航向代价则不能。这只证明固定状态的选择机制。第四轮单独去改点代价的整回合在850秒发生缓冲侵入，不能由固定状态选择直接预测闭环成功；单独去航向代价未做闭环验证。证据：`route_cost_case009.json`、`route_cost_case009_component_scores.json`。

**同一简化也存在显著退化。** 新开发场s371_017_channel_slow_3000中，路线成本版本3087秒到达、实际改点41次；前向评分版本2052秒、改点23次。首次不同目标在t=101应用，物理轨迹在t=102分离。t=100同一物理状态到旧目标431.171m，路线成本改善仅15.106m，刚超过阈值；复算继承评分的改善13.476，未达阈值。此处没有单独记录前向评分器t=100的完整候选日志，复算与直接日志已区分，不能把分歧后t=120的状态视为同一输入，也不能把整段1035秒差异归因于单次切换。后续第四轮已比较只去改点代价和100m有效持有门，完整结果如上；没有把一个局部救回案例当成选型依据。证据：`route_cost_regression017.json`、`route_cost_regression017_component_scores.json`。


100m有效持有门改变valid状态，同时影响urgent、旧目标注入、改点代价、保持与阈值；不是单一切换时机消融，也不保证100m内一定改点。短目标仍按原LocalFrame将目标编码到[500,0]，本轮未证明短目标违反归一化。
