## 补证一：静态数值编码

三个新模式均使用边界模式选出的障碍集合及顺序，再分别输出 `max(0,d−排除半径+40)`、原始中心距离d、`min(d,150)`。截取阈值150m、最多两个障碍、bearing、低层权重、连续记忆和Relay保持一致。8891个已有实际状态的离线接口核查通过；八个boundary重放与旧R6科学轨迹逐值相同。

8个已见实例包括四例救回并集、一个已知失败及三个正常／代价对照，不是随机泛化集。结果边界7/8、匹配原始中心7/8、匹配截断中心6/8。四个原关键救回均被原始中心复制，故主张从“数值变换必要”收缩为“整项输入接口曾有条件性收益”。边界对原始中心共同安全7场平均快35.43秒，最差慢6秒；样本选择不允许外推总体效率。

## 主张与证据边界

| 可以支持 | 不能支持 |
|---|---|
| 在已定义理想计算场景中，参考特异预测有时避免实际缓冲侵入 | 实时执行、实体碰撞减少、形式安全保证 |
| 搜索相对已定义的简单保持规则有条件收益；同状态证据支持选择差异 | 所有简单规则必然不够，或15秒配置必要／最优 |
| R8历史30短场30对28、4长场4对3是对应版本的独立结果组 | 把历史、新确认、不同交付条件合并成一项成功率 |
| 新集12场保留安全，但相对反应式无安全增益且有航时长尾 | 泛化到任意场景、普遍安全／效率提升 |
| R6整项输入适配有条件作用 | 54/54全由单一距离公式造成 |

篇内主要未解决问题是**何时干预值得其代价**：新确认的反应式已经安全，现有guard触发仍造成54秒和271秒代价；候选搜索优于盲目保持并不证明触发本身必要。作者最终回应指出这一点，协调者采纳，不用范围外的部署问题遮住篇内负结果。本文只作条件性接口适配与闭环诊断主张，不宣布更优导航方案。

另一个部署边界是预测与执行在计算等待及风变化下的可靠性。R9 mixed3额外5秒等待反例仍在：预测82.692m、实际−0.949m，最大位置误差140.048m。没有凭顺序单因归于某模块。本篇不解决任意延迟；若改称可部署实时避碰，就必须重新研究。其余范围限制包括单目标低速恒速会遇、有限候选、继承模型条件、未知公众部署许可与署名状态。
