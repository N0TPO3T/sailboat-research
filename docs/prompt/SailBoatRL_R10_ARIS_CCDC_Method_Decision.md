# SailBoatRL R10：问题优先的选型与作者—模拟 CCDC 审稿人对抗审查

请使用执行端已经安装的 ARIS，继续现有项目。先读本地技能说明，使用实际支持的子代理／分离会话和实验能力，不猜命令、不重新安装科研平台。本轮不是默认继续优化 R9，而是基于已有成果确定一篇 CCDC 稿件真正采用的问题、方法和主张；必要时通过少量关键实验消除决定性分歧。

## 1. 目标、选型原则和有效授权

用户目标是以合理工作量完成有实质证据的 CCDC 投稿，提高稿件质量与可接收性，而不是追求顶级原创性、穷尽全部航行问题，或不断增加版本。

**问题、方法和证据是主项，会议适配是低权重辅助项。** 作为内部讨论原则，约 90% 重视问题价值、假设与实现的一致性、实际作用及归因、代价和完成成本；约 10% 考虑 CCDC 主题适配与紧凑的控制／决策论文表达。这不是官方评分标准，不估计录用概率，不以加权高分抵消技术错误或证据缺失。无需建设打分平台。

成熟方法的采用、必要接口适配和系统化应用验证可以保留。无需新网络、新定理或强行命名新算法；但也不能把未注明来源的照搬、只换名称、运行成功或修复公共错误全部写成原创贡献。要交代相对已有工作真正增加的知识或可复用能力。

允许修改、训练、替换低层及高层，调整输入表示、估计器、预测器、记忆和参考交付协议；不强制任何模型改动。14D/18D、Relay120/160、500m、15/60秒、30m guard、25秒时隙都只是已有配置，不是永久限制。完整地图、无直接风观测和仿真导航是当前研究范围；内部因果估计、已知动力学预测、离线特权标签允许，在线读取真实未来禁止。重大改变题目或传感信息条件时说明理由并征询用户，不在本轮自行扩成真机、感知开发或完整多船 COLREGs 项目。

更新本项目当前有效任务说明及 HANDOFF，注明本轮是“主方法与论文范围决策”，同步给子代理。历史说明保留并标为历史，不改系统级安全或资源权限。过去“静态必须是主线”“动态只能附录”的建议均为待检验判断，不是预定答案；最新版本也不自动优先。

## 3. 校准 CCDC：看实际样例，不猜审稿人口味

先做一次小规模校准，原则上和材料整理合计不超过约2小时，不花整轮查会议档次。可复用已经核验过的原始资料。目的不是找到“容易发表”的例子，而是了解相关领域已有论文怎样定义问题、组织方法与提供证据。

查看目标届官方征稿与投稿说明；年份、截止时间、页数、匿名和 AI 披露等规则不沿用旧对话。访问失败就写“本轮未核验”，用已有证据继续方法工作，不从混杂搜索摘要推断正式规定。会议范围与格式是正式条件；某种算法偏好通常只能由有限样例推断。

选择近两三届约4—6篇与规划、机器人／船舶控制、学习控制或模型预测相关的正式论文，兼顾经验方法与分析型方法。尽量读取2篇可获得全文的相关方法和实验；不足则明确全文、摘要、元数据三种访问层级，别用摘要声称已检查消融或证明。不要只挑最弱论文或最佳论文代表整个会议。

## 4. 作者与模拟 CCDC 审稿人：分别工作，再基于证据交锋

使用两个分离的子代理或会话，而不是同一回答里换两种口吻。优先使用现有已授权调用；不同模型可用时可以采用，不购买新服务、不上传私有材料到未经授权的新服务。相同模型的不同会话也可以，但标注同家族内部评审，不称独立认证。工具确实不支持分离会话时说明限制，做透明的串行替代，不伪造多代理调用。

审稿人是**模拟角色**，没有真实CCDC身份、不代表程序委员会，也不知道真实录用阈值。对抗对象是主张与证据，不是为了赢辩论或一味拒绝。执行协调仍由当前 ARIS 主任务完成，不另搭一个多代理平台。

### A角色：作者／研究负责人

先提交最多2—3张等详细程度的候选方法卡，建议比较：

- A：以R6的安全边界观测适配和连续航行接口为主；动态不绑定为必需成果。
- B：以R8/R9的候选闭环预测避碰为主，清楚选择非实时机理仿真或交付受限协议，不能两种结果混写。
- C：只有A和限定动态扩展构成同一明确问题、额外部分有独立作用时才保留组合；也允许提出证据驱动的更简单替代，不强制第三条。

每张卡用一页左右说明：问题、输入与信息条件、核心假设、方法/公式/实际代码、与继承及最近文献的关系、最强正向证据、最不利反例、可支持的主张、还缺的关键证据、完成成本。静态与动态用不同任务难度，不能比较54/54和12/12给它们排名。

作者应为每条合理候选给出最强但诚实的论证，不能预设R6胜出或R9更先进。可反驳审稿人的不相干要求；每项反驳必须依据任务范围、原始证据或文献，不以“CCDC比较容易”“别的论文也这样”为理由。不能靠不断缩成“只证明代码能跑”而宣布科学问题解决。

### B角色：模拟 CCDC 应用控制/决策审稿人

先独立阅读相同事实摘要、来源校准和候选卡，必要时查看原始记录；首次意见前不要读取作者预写的反驳或前任agent的推荐结论。先复述每个候选真正解决什么，列出最强接纳理由，再列最多3项会影响选型的核心问题。

每条意见写明：

`质疑 → 证据/具体位置 → 影响的主张 → 严重程度 → 什么补证或修改足以解决`。

把意见分为：
1. **有效性/真实性问题**：定义不一致、偷用未来、把侵入当普通异常删除、假设与实现冲突、借用贡献未归属等。不能靠风格加分抵消。
2. **主张所必需的证据缺口**：核心收益可能来自公平性差异、预测与执行不一致、效果集中少数案例等。给最小有区分力的验证，不机械要求所有基准/多船/海试。
3. **可接受的范围限制与表达问题**：明确的仿真设定、有限泛化范围、未声称的理论/硬实时、篇章和图表改进。不得把所有限制都升格为必须再开一个研究项目。

同时辨别“采用已有方法但有清楚适配及新证据”与“只换场景/参数却没有可解释价值”。不以没新网络、没新定理、没新训练直接拒绝，也不因CCDC定位而自动认可。

特别核对：R6整项距离适配是否被误写成单一公式作用；R8/R9不同条件的数字是否被拼在一起；误干预长尾是否隐藏；静态模拟结论是否被写成实时系统；公共修复和借用模型是否被算成新算法。也要判断作者是否过度承诺，缩小主张能否合理解决，而不是提出无限外延要求。

### 交锋与有限迭代

流程为：作者候选卡 → 审稿人首次独立意见 → 作者逐条回应 → 少量决定性补证/必要修改 → 审稿人复核 → 协调者选型。

默认两轮正式交锋足够，不以双方同意、审稿分数上涨或“接收”口令作为终点。允许保留分歧。第一轮后把争议归成：事实可直接核对、必须实验判别、仅需清楚限定、超出本篇且不做。优先选择1—2个最可能改变选型的实验/分析；这不是禁止额外必要修复的永久上限，不重跑所有旧方法矩阵。

补证后保留同一批质疑的状态，避免换reviewer后重新开启全部要求。若仍不同意，协调者根据证据说明取舍，不投票逼一致、不自动创建第三个审稿体系。

## 5. 用研究解决分歧，不停在模拟评审报告

不要为了完成“对抗审查”只交辩论文档。对已确定的重要、预算内可解决的缺口，作者继续实现和实验。方法可改、范围可缩，但目标是明确一个值得继续写成稿件的方法，不是无限循环。

可参考的判别问题，不强制全部做：

- 静态候选：在同模型、匹配可用障碍集合/可见范围/排序下，编码是否仍起作用？原训练距离意义和新安全边界如何对应？组合适配是否可以作为不可拆分的合理方法来说明？
- 动态候选：依据原始日志区分协议差异与预测误差；在声明交付条件内，新机制相对简单预测/反应式方案是否值得计算与航时代价？25→30秒反例具体限制的是哪项主张，不预设必须彻底解决任意延迟才可写经验仿真文章。
- 组合候选：静态输入适配和动态预测能否在同一最终系统中分别保留作用？若没有新增验证，只能作历史机制证据，不能把R6/R8的不同配置结果拼成新系统性能。

允许文献适配、简单重标定、模型微调/替换和协议调整，不为创新增加模块。选低成本但有效的路线，也允许在主要方法不成立时回到较简单、有证据的候选。大规模全新选题或扩预算另询问。

开发可使用所有已看过的R1—R9场景和失败。用于改方法/选型的数据不能再次称未见测试；重复场景、多候选/重叠窗口不是独立样本。主张与方法暂定后，才安排真正未用于调参的确认，必要规模根据问题和开销制定，不设“必须100%”“必须p<0.05”门槛，也不以不显著推断等价。确认结果不好时公开结果并修正定位，不能继续抽样直到赢。

同一任务下公平对齐信息、地图、外生风/目标运动、初始状态、真实安全与到达定义。被研究的输入、控制器和时序可以不同，但差异要明示并有适当对照。静态/动态、自然任务/人为风险、理想交付/实测或模型延迟分开。保留失败和成败交换，条件航时说明分母与尾部；不把提前终止当提速。

## 6. 最终选型：选一个论文中心，不再让所有分支成为必需

协调者不能只复述“条件性收益，建议进一步研究”。本轮结束必须作出带依据的**方法与论文范围决策**，不预先决定哪条胜出：

- 主问题、最终方法和适用假设是什么；
- 哪些模块进入主方法，哪些仅为对照/扩展/未解决边界；
- 相对文献和合理基线，最小且真实的贡献是什么；
- 现有证据已支持到哪里，还有哪些投稿前补证/表达工作；
- 哪些方向本篇明确不再追逐，以及什么新证据才值得重开。

约90/10优先原则只帮助在科学上可辩护的方案间取舍。CCDC风格只能影响范围和表达的匹配，不能把坏方法包装成好方法。审稿人意见不等于真实录用结果；最终投稿由人类作者确认。

“固定研究主线”是本篇的工作决策，不是永远禁止未来改模型。确认选择后避免因零碎新建议继续膨胀范围。若没有候选具备足够的最低实质证据，可以明确写“当前未达到方法定稿”，但必须指出一个具体缺口、为何已有方法无法支撑及一次可执行的补救；不能为了满足交付要求硬称完成，也不能只罗列十个未来方向。

## 7. 预算、权限和最小工程

沿用之前的建议上限，须服从执行端已有的实际授权：总墙钟不超过24小时，最多1张已明确授权GPU、累计不超过12 GPU小时；CPU先按最多4个单线程实验工作进程起步，内部并行和子代理共享配额。GPU空闲不代表授权，缺少确需资源时集中一次确认，其余工作继续。模型无须改则无需训练或占GPU。

不强制8轮开发，不规定固定时刻必须宣布方法成熟，也不为花满预算继续实验。两次审查不是新的预算。只需简短计划、少量针对性日志和原工具，复用runner、绘图与交接，不新建多代理平台、通用审计或评审仪表盘。

保护上游、旧配置、原始结果和用户未提交修改；新输出独立目录。不自动push、投稿、采购或公开材料，不在审稿模拟中向未授权服务披露私有资产。可以在新分支使用合适的外部代码并保留许可和引用。
