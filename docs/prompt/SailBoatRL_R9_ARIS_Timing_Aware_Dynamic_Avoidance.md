## 3. 研究推进：有方向、有分支，不预先锁死实现

写简短计划后持续执行。以下是相互关联的研究问题，不是逐关向用户审批，也不是所有技术都必须实现。

### A. 先知道时间花在哪里，并明确交付协议

从短、长历史及名义／进入避让／保持／退出等实际决策状态中，选少量具有区分力的样本。测量风拟合、状态与历史准备、网络前向、预测动力学、几何与路线检查、候选评价，以及必要的数据搬运／结果应用成本。已有计时足够就复用，缺少才用简单 profiling；不要创建通用性能平台。

记录硬件、线程、并行负载、候选和预测步数量、历史长度。区分 profiler 插桩时间、无插桩墙钟、累计 CPU 时间、离线写日志及冷启动。若 GPU 计时，包含同步及必要搬运，不能只测异步 kernel 提交。先在固定配置上解释热点，再据证据挑最值得的改动。

说明真实接口：低层多久更新一次、预测以哪个时刻为起点、计算时执行什么、多久请求新规划、旧结果何时失效、候选无效／超时如何处理。高层不必等于低层频率；把周期由 15 s 改成 60 s 也不自动证明可用，需要验证会遇期间的效果。

### B. 保留预测的决策作用，选择最省事的改进路线

优先考察实际热点支持的办法：共享候选公共前缀、缓存不变数据、批量网络计算、合法并行、去除重复构造／反复历史重算、粗到细筛选、按需要分配预测长度或重评估频率。没有必要就不实施。

这些若声称仅是实现优化，应在相同输入下比较预测、候选选择与动作的等价性或明确数值容差；若改变了预测精度、历史内容、可选机动或动作，应当作方法变体，重新检验闭环效果。不能把截断真实记忆、改积分步长的影响当成零代价加速。

也允许根据证据采用独立简化动力学、轨迹片段检索、候选条件的学习模型、策略蒸馏或控制器适配。无需为用了 GPU 或新网络而制造贡献，也不能因旧授权习惯排除这些路线。近似预测器须与实际执行对象匹配；低层改变后不能继续把旧预测误差结果当作新模型证据。

风险留量、保持和退出可以研究，但不继续无依据扫阈值来“保住 30/30”。优先看候选安全判断、危险漏判、错误干预及预测／执行协议差异，不只追求平均位置 RMSE 或更快的函数调用。

需要来源时读 R8 已选的 GVO 原文与实际相关的预测控制方法；新机制超出原框架再补少量一手资料。准确区分采用与适配，不要求重新泛查会议等级或凑新定理。

### C. 让计算交付条件进入真实闭环实验

必须至少得到一种明确、可复现的时间处理方式，不能只把计算耗时加到回合最终航时上。

可以采用带事件队列的离散时间实验，不要求运行实船或开发真实实时服务：
- 在观测时刻保存不可变输入快照，内部模型只访问该时刻允许的信息；
- 结果在约定的 ready 时刻之前不可用于本船决策；
- 等待期间按明确的原计划／最近有效参考等协议执行实际低层反馈，本船、目标船及风时钟都继续推进；
- 结果可用时处理状态陈旧、任务已经结束、目标已变或过期结果等情况；没有必要就只允许一个待决计划，避免建设复杂调度器；
- 历史记录只写实际观测与执行动作，不用候选模拟历史替换真实历史。

等待期间不能默认原地停车，不能机械重复“上一帆舵增量”来冒充低层闭环，也不能把本应过期的预测第一段直接当成当前状态下动作。具体安全降级或保持方式可以研究，但不声称其本身保证安全。

时间处理可基于同硬件实测、校准延迟模型或明确定义的延迟工况。三者要标清楚；估计延迟不等于实测部署。使用仿真逻辑时间推进完全可以，但延迟长度、ready/apply 逻辑和等待期行为必须能复现，不能人为选一个小于实际开销的延迟来宣称实时。

逐次记录 `observation_time / plan_start / plan_ready / reference_apply`，同时保留测得的墙钟开销。状态年龄不仅是网络耗时，必要的风拟合、历史编码和交付也计入相应环节。若保留 1 Hz 低层假设，需要核实影响它的计算或单独声明执行资源和假设；低层偶发超时不能一概忽略。

异步、预先规划、带截止时间的搜索、状态前推等都可选择，不强制同时实现。禁止用实际未来状态初始化所谓延迟补偿。离线最好分支可以诊断，不是正式在线答案。

## 4. 如何判断改进：小规模开发，关键比较，再适量新实例

优先从已见 R8 真正的途中侵入案例、成功避让、`endpoint_5` 绕行反例、长历史高耗时状态和无需干预的普通案例开始。不要只测试最快的短历史，不要求所有边界一次解决。

建议围绕以下比较组织，而非机械全交叉所有旧方法：

| 比较 | 回答什么 |
|---|---|
| reactive 与旧 R8 理想交付 | 保留已有机制参照；后者不是理论最优上界 |
| 同一 R8 按声明延迟交付 | 原有收益对实际决策延迟有多敏感？ |
| 新方法按其自身实测／声明时间条件交付 | 改进后是否能保持避让作用，并减少计算与过期风险？ |
| hold60 或更简单的成熟方案 | 新复杂度是否必要？不要把已有同样成功的简单配置排除 |

实现等价加速、协议变更、模型近似和控制器变化尽量用最有区分力的 1—2 项对照说明，不要求每一行代码一个消融。如果只有组合有效，就明确组合主张。周期比较要说明保持、重评估、风拟合刷新是否同时变化；不把耦合结果归因于单个参数。

公平条件：场景、物理规则、可用观测、任务判分和硬件资源配额可比；方法可以有不同实际耗时与组件。不要把所有方法强行延迟到最慢者，也不要只让新方法免费计算。公共 bug 和简单终点可用性处理公平用于适用对照，不把基线的程序前置条件失败全部写成新算法避碰优势。

方案初步有依据后，再在预先定义的新实例上确认一次。保留途中冲突、高压力、普通与错时会遇、终点占用分组；有选择地覆盖 1/3/5 km、静态回归及机制激活时的目标转向或延迟变化。规模按实际成本和要辨别的效果决定，不强制千回合，也不因为所有方法都成功就不断更换种子寻找优势。

本轮所有已查看 R8 场景均可用于开发，原标签与结果保留。新实例一旦用于选参数就明确转为开发；最终验证不按胜负筛选。源回合、同前缀分支与重叠预测窗口不是独立测试样本。若训练，用开发数据按源场景划分；有学习收益后再安排足量交互和适当训练对照／重复，不用一个未学起来的短运行否定路线。

## 5. 指标、解释与成功标准

完整安全到达为主；动态缓冲侵入、静态侵入、实体碰撞、超时、无路和过期／无可用计划分别记录。侵入后再到达不恢复成功身份；停止标签不能代替物理安全分类。途中避碰与终点占用收益分开，不把无干预成功归于新模块。

在明确的共同安全集合比较航时、航程和误干预代价，给平均、中位、尾部和最坏例，同时给配对新增／损失与全任务完成摘要。惩罚失败的综合指标只作明确定义的辅助，失败早停不算更快。不要以少改点、少换舷替代推进与安全。

计算指标包括决策延迟分布、观测到应用的年龄、期限错过和过期丢弃、长历史开销，及相同输入下优化前后的测量。给样本数、P50/P95和最大值，样本足够时再给更高分位；有限实测不能写成最坏情况保证。累计 CPU、平均回合墙钟、决策延迟分开。

预测比较对齐实际采用的候选、未来反馈与共同时间窗口；只观察到前 15 s，就不称完整 60 s 验证。同时披露未执行候选无法获得的真实结果、被终止／改点截断的窗口。30 m 经验 guard 不是已证误差界；“未观测到错判安全”不等于排除了错误。

本轮不设置“必须全成功”“必须训练”“必须新定理”“必须硬实时海试”。有价值的结局可以是：
1. 保留动态收益，并在明确硬件／延迟条件下得到可信、代价合理的完整方案；
2. 更简单的候选协议或模型在可接受代价下更合适，采用简单方案；
3. 经合理尝试仍只能支持非实时理想模型结果，明确是哪项假设限制了它，并给出据证据收窄的论文定位。

第三种不是第一步不顺就立刻停止的理由。也不因动态尚未成熟而否定 R6 的独立静态证据。方法可能成为本篇核心组成或有限扩展，结论应由本轮证据决定，不继承 agent 上轮建议为永久限制。

## 6. 保持任务可信，避免扩大成新工程项目

继续使用当前单个低速目标船、已知静态地图、无直接风传感器的任务作为起点。R8 使用已知动力学加局部因果风估计；这与“完全未知模型”不同，最终说明必须准确。可使用内部模型和开发期特权标签，不访问真实测试环境隐藏风／未来目标动作／RNG，不改变真实环境来方便预测。

保留外生目标运动、同步时间和带 ID 的真实障碍历史。动态 85 m、静态实体外 60 m、终点 10 m 与 1.8 s/m 时限是当前共同协议，不是法律标准。若发现物理／几何定义错误，说明依据并统一重评受影响方法，不能为单个方案放宽判分。内部预测器可简化，评价用的真实动力学和安全计算不能为了跑得快被悄悄放粗。改变控制频率不得增加执行器每秒实际能力。

本轮不主动扩展多船博弈、全套 COLREGs、真实传感或海试；确有证据表明需要改变主要信息／任务设定，再集中询问。原论文引用与源代码许可照常保留。

复用已有 runner、预测分支、绘图与日志；只增加必要计时、事件和测试，不建实时操作系统、通用调度平台、仪表盘或新仿真器。保护上游、旧权重、旧结果和他人改动；在新分支／目录研究即可，不重复全仓哈希与备份，不自动 push、公开原始资产、购买服务或投稿。

## 7. 自主预算与何时结束

沿用此前建议上限，用户可在启动前修改：总墙钟最多 24 h；最多 1 张明确获用户或调度授权的 GPU，累计不超过 12 GPU h；CPU 先按现有最多 4 个单数值线程实验进程，在确认配额内调整。内部候选并行与外部回合并行共享总配额，不层层倍增。所有子任务、训练、审查和交付共享一个预算，不重置账本，不强制固定迭代数。

GPU 可见或空闲不等于有权限。若确需但不明确授权，集中一次确认具体需求；其他已授权研究继续，不把缺确认写成禁止训练。只做 CPU 已有方法足够时也无需强行申请 GPU。短测吞吐后再分配训练和实验资源，保存中间成果和可续跑状态。

普通实现、开发调参、去掉无效模块和转向有证据的备选方法连续执行。一个判别实验结束或 review 完成，不自动结束整轮；关键缺口尚可在预算内处理时继续。已有明确结论、合理备选均遇到证据边界、资源已满或真正权限阻塞时停止。没有必要耗满 24 h，也不以“用得少”作为贡献。
