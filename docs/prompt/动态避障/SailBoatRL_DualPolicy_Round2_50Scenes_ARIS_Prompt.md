## 2. 首轮事实：作为开发材料，不冒充第二轮结果

首轮固定24场：normal 17/24，avoid 22/24，range 21/24，risk 23/24。专家相对normal救回7场、丢失2场；risk相对avoid救回2场、丢失1场；risk相对range救回2场、无新增损失。

这些配对计数意味着：normal与avoid共同安全15场，只有avoid安全7场，只有normal安全2场，两者均失败0场。它支持整回合成功集合存在互补性，**不是在线路由可达到24/24的保证，也不能使用事后赢家选择作为在线算法**。

首轮四组共同安全只有12场，risk比avoid平均慢约8.17秒。两者直接共同安全应为21场，完整配对效率尚需从日志补齐。当前avoid/range/risk都计算两个Actor，接管时间更少不等于计算更省。

已采用的环境与接口：
- 固定500 m终点、1 Hz控制、700 s时限；首次40 m中心安全域违反即终止。40 m是当前继承协议，不是A线的85 m。
- 0—1艘恒速低速目标；前向120°、150 m内直接提供理想位置和当前速度；不开发感知模块，不读真实风。
- 离开视域停止真值更新，最后观测常速外推最多5 s；过期后动态8维槽置零。静态已知位置可长期保留，动态位置不能照搬。
- 专家26D：原18维加相对位置2、相对速度2、visible、age、valid、seen。相对速度已按四自由度运动学修正，含横摇投影；旧18维normalizer冻结。
- normal用原streaming LSTM；avoid用10步真实历史、零初态重算。不是同一记忆协议，不能把全部效果归因于新增速度输入。
- 本步顺序为合法观测→路由→Actor前向→只执行所选动作→原执行器与动力学推进→记录实际命令。不要改回A线“旧动作先算、新参考下一步应用”的另一种接口。
- risk原设置：30 s相对运动CPA、65 m进入阈值；交还要求距离>75 m、远离和任务方向接近检查，持续3步且接管至少5 s。range使用可见/有效缓存接管。失联交还共用已实现的速度上界圆盘条件，依赖目标速度≤1.6 m/s；不是完整未来安全证书。

最终训练是Actor热启动，不是师兄原训练的精确续训。继承Actor参数冻结，只更新两个输入层新增8列，共4096参数；Q、目标Q和优化器等新建并实际训练。原设置包括：Actor/Q学习率3e-4，batch32，每4环境步一次Q更新，500次Q预热后每4次Q更新一次Actor更新。源代码是具体实现依据。

首轮选中28617步检查点；训练中途先后加入无效动态槽屏蔽、修正相对速度。因此它有可用性能证据，但不是“从第一步就使用最终协议”的独立训练重复。本轮保留全部旧失败权重和记录，不从它续训两次就称为两次独立训练。

这些是接手起点，不是永久限制。允许对已定位问题作必要的小修改；不同时无依据地改奖励、观测、历史长度、路由和全部网络。

## 3. 先做现有日志诊断：集中五个关键回合

不要重新对全部96回合进行一整套重复审计。先从原始逐回合记录确认以下五个scene_id及实际结局：

1. avoid失败、normal及两种路由成功的两场：一场late、一场headon。
2. range额外失败，而avoid和risk都成功的两场late。
3. range与risk共同失败，但avoid始终运行成功的一场cross。

上述身份应由配对表核对，不凭类别标签猜ID。late只是名义错时生成标签，不保证实际无冲突。

每场整理一条紧凑时间线：首次可见、风险条件、实际接管、视域丢失、缓存过期、实际交还、首次违规/到达。查看对应真实动作、航向/航速、参考和同步间距，回答问题更可能发生在接管时机、接管状态、专家动作、失联表达还是交还。

尤其检查两点：

**接管状态不匹配。** 专家从初态始终运行成功，不代表它能从正常策略已经到达的任意状态救回。训练的10—45 s正常前缀不一定覆盖路由实际接管分布。

**路由与专家的失联信息不一致。** 路由知道见过目标且风险未解除，但专家过期动态槽全部归零，10步窗口滑过后可能不再包含任何目标信息。先查这种状态是否与失败/长期接管有关，不直接取消mask。首轮取消过期age/seen曾修复两个超时，不能忘记反证。

同时从已有24场补齐：
- avoid−normal，共同安全预计15场；
- range−avoid，共同安全预计19场；
- risk−avoid，共同安全预计21场；
- risk−range，共同安全预计21场。

给出配对得失、共同安全航时/航程均值、中位、最大退化、更快/相同/更慢数量；分母以实际重算为准。四组共同12场可以保留作统一参考，但不能替代两两比较。

## 4. 仅在日志无法定位时补少量同状态分支，然后定向修正

先优先处理共同cross失败及最有解释力的一个有利案例。必要时复现真实前缀，在少量事先选定时刻比较“立即交给专家”“继续正常控制”或“暂不交还”。每项分支明确后续执行协议，并运行到完整任务结局，不仅比较几秒钟的距离。

同状态必须恢复物理、帆舵设定值、任务/目标船/风时钟、normal记忆、专家真实窗口以及路由计时。两个网络的隐状态不能互相复制，不把一组运行后的状态与另一组同时间但不同前缀状态当同输入。不扫描几十个时刻再挑事后最佳分支。

已有的“继承权重＋10步窗口、未训练新增列”初始化专家，可在关键状态上作为小对照，区分窗口处理与训练后的动态适配；不要求新增一整列全量基线。

依据诊断选择修正，不要求以下全做：
- 接管状态分布不足：加入实际路由产生的合法接管状态或相近开发分布，优先补训练覆盖。
- 进入过晚或无谓进入：调整最相关的进入条件，用原普通/错时成功任务检查代价。
- 过早交还或交还后再次接近：修复退出/接回条件，不靠永不交还获得安全。
- 失联后信息丢失：以最少字段区分未见与已见但不确定，必要时配合训练；不提供过期目标真位置，也不盲目恢复原来会致超时的age/seen数值。
- 实现错误：修复适用的公共代码并重新验证受影响方案，保留旧记录。

如果现有专家/路由没有可解释的错误，不强求修改；可以直接对当前最终定义做独立训练与新确认。若普通协议下无足够机动能力，有限候选分支失败也不能证明物理绝对不可避。

默认保留轻量的受约束输入适配。确有证据表明容量不足时，可在开发阶段尝试一个有针对性的扩大训练范围，但不能直接回到无依据的全量微调，也不把4096参数设成未来必须遵守的限制。

对每个真正影响结果的修改，用一小组已见任务作前后比较，说明改变了什么。共享交还修正应公平用于适用的range/risk；两组若同时区别进入与退出，就如实称组合路由比较，不包装成单阈值消融。

## 5. 最终训练方案固定后，做两次独立训练

从训练第0步就采用最终确定的：无效槽处理、相对速度定义、归一化、历史规则、奖励、接管分布及更新比例。若开发阶段修改它们，最终两个运行应使用一致版本，不能拼接旧阶段的成绩。

先根据吞吐固定两次相同的环境步上限与开发评估频率。可从约3万—5万环境步这一量级估算，不把它当收敛保证；当前31k只是预算参考。开发结果确需更多训练且预算允许时，在最终确认前统一确定延长规则，不能只给表现差的种子秘密追加到它赢。

检查点按共同的固定开发标准选择：优先安全完成，再用明确失败惩罚的开发航时等已有规则；两个种子用相同标准。旧12场开发集与本轮已看过的24场可用于开发，但需提前决定哪些进入选点/标定，不不断增删选择集。

两个最终检查点都选定、配置固定后再运行新50场；不能看到第一个种子的测试失败后修改第二个的奖励/路由。每个种子的avoid、range、risk都必须用该种子同一专家权重和normalizer。

保存实际训练步数、Actor/Q更新数、开发选择记录、学习曲线、模型/目标Q、优化器、replay、normalizer和RNG等已有恢复状态。沿用已有回合边界恢复机制，不重复建立恢复审计平台。保留两次训练，无论其中一次结果是否较差。

首轮selected检查点保留为历史对照与诊断起点，不因测试种子不同冒充最终方案的第三个独立训练运行。两个新种子只能提供有限的重复性信息，也不是充分稳定性证明。

## 7. 指标：围绕互补性和路由，而非只看一个总成功率

每个训练种子分别报告：
- 四组安全完成/到达/违规/超时/其他失败，全部50场在分母内；原终止原因与物理安全结果分清。
- 六类任务分项结果，尤其普通航行、错时标签任务、实际冲突与边界视场情况。
- avoid相对normal的得失，risk相对avoid的得失，risk相对range的得失及对应场景ID。
- normal与avoid的共同成功、仅normal成功、仅avoid成功、共同失败四格表；与路由实际结果对照，但不把事后选择当在线性能上界。
- 每对方法各自共同安全集合的航时/航程均值、中位、最坏退化和更快/相同/更慢数量。失败停止时间不当到达时间。
- 切换次数、接管时长、是否成功交还、不可见时发生动态违反及接管/交还后的关键事件。切换少或接管短本身不是收益。
- 真实决策开销和测量范围；计算两个Actor就如实写，不把接管降低称为省算力。

安全继续采用原同步相对线段口径；它不是连续ODE/船体安全证明。40 m不可事后缩小，也不混入方案A的85 m。none且无静态目标的距离保留null，不混入有障碍最小距离平均值。

不要求为了得到p值而增加样本，也不以50/50或两次相同总数声称普遍安全/策略等价。若两种子对路由作用方向不同，这就是首要结果；若avoid始终运行最好，接受该结论。不要为了路由必须成功继续堆阈值。
