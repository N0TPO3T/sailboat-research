## 4. 首轮环境：直接提供视域内目标状态，不做感知系统

### 4.1 观测假设

首轮建议采用：

- 前向 120°，即相对船艏 ±60°；中心距离不超过 150 m。
- 视域内目标直接提供仿真当前位置和当前速度，转换为本船可用的相对量。目标 ID、可见标记、观测时间可直接由仿真提供，不做检测或数据关联。
- **“视域内速度也可直接获得”是本轮为隔离控制问题采用的理想化输入假设，不是用户已经确认的实机传感器能力。** 在 README 首页注明，后续可研究去速度或估计速度，本轮不做这部分。
- 不引入像素、噪声标定、测距、EKF/KF、视觉网络、AIS、相机标定或真实传感器依赖。
- 本船使用原环境的运动与帆舵状态；风作用保留，但正常策略、避障 Actor 和路由第一版不读取真实风或未来风。训练奖励和离线评价可使用必要环境真值，不能泄漏给在线决策。

几何过滤可以写为：

```text
visible_i = distance_i <= 150m
            and abs(wrap(bearing(target_i - own_position) - own_heading)) <= 60deg
```

视域随物理船艏，不随目标点或策略意图旋转。第一版用二维扇区，不建三维相机系统。

### 4.2 离开视域后的简单处理

目标出视域后，**停止向在线模块提供其真实位置/速度更新**。不能像静态障碍那样“见过一次，以后始终从仿真读取动态真值”。真实环境仍让目标正常运动，安全判分仍覆盖不可见目标。

为避免一转弯目标出视野就立即切回，允许一个最小的历史缓存：最后一次可见位置、速度、时间和有效状态。短时丢失可作常速外推，先以约 5 s 为开发初值；必须标为预测/陈旧输入。无需估计协方差或建设跟踪器。

超过缓存有效期后，不继续输出虚假新鲜观测。用缺失/年龄信息和明确的路由保护规则处理；“缓存过期”不作为已安全通过的证明。若持续不确定，避障策略可继续执行并尝试推进，真实任务超时/失败如实记录，不让船被假想刹停。

### 4.3 船舶与任务

- 首轮用 0 或 1 艘移动目标；低速从 0.5—1.5 m/s 作为开发起点，初始位置、航向、会遇时刻随机。
- 第一阶段随机参数后保持恒速，训练及基本交接成立后再加入少量有界缓慢转向。不要每秒独立随机换方向，不瞬移。
- 一轮预算充足且单船效果可解释后，才选做2船小测试；不把多船全覆盖当首轮前置条件。
- 先开阔水面，再加入少量静态障碍。保留原风场、动力学、动作约束和目标导航能力；所有比较共用相同场景定义。
- 必须包含无目标、远离、错时通过等非冲突情况，以及横穿、追越/接近等风险情况。外部目标运动预先给定或由固定随机过程产生，不因本方法失败就临时让路。
- 安全定义优先继承实际师兄环境，先查明“中心距离阈值”还是“实体半径外缓冲”。师兄学位论文静态协议采用中心40 m安全域；A线的85 m是另一套实体/缓冲约定，**不要不加说明地搬过来，也不要将两者说成同一标准**。
- 第一轮在配置中明确动态目标采用的排除距离及其来源，所有方法共享。若需要改变实体尺寸或安全协议，要在比较前说明，不按实验输赢修改。
- 先用几条代表遭遇检查150 m首次观测是否留出合理机动空间。发现极端不可避/来不及的设置就报告原因，不能悄悄扩大感知或删除失败。

## 5. 方法：动态专家是真正的新训练策略，不是S15换名字

### 5.1 正常策略 pi_nav

优先使用已加载正确的18D注意力 Actor及其normalizer，原权重只读保留。它负责正常航行及已有静态避障。

合法的视域内动态位置也可通过原距离/方位槽位适配给它；不能为了突出新方案故意让唯一旧基线完全看不到船。未提供速度的旧结构与新增速度输入的新专家仍是不同能力配置，区别如实写清。

### 5.2 动态避障策略 pi_avoid

从已有策略兼容部分初始化，扩展动态观测输入，使用原SAC体系优先进行训练。至少包含本船状态、任务参考以及动态目标的相对位置/距离方位、相对速度、可见性和必要的观测年龄。

不锁死输入必须18D，不要求重新发明网络。先用一或两个固定目标槽位及有效标记即可，不必为一个目标实现图网络或Transformer。扩展输入后核对字段顺序和归一化；两个策略分别使用匹配normalizer，不把新特征直接塞进旧统计。

训练入口优先复用师兄实际实现。若只有Actor/normalizer而没有匹配Critic、优化器和replay，这只能算Actor热启动：新建必要训练状态并说明，不能称精确续训。如果原训练代码可用，让它正常运行优先于重写RL库。

循环策略训练使用与实际模型对应的序列、记忆初始化或burn-in方式。不要用任意打散的单步样本和无来源的隐藏状态，却声称已经正确训练了SAC-LSTM。也不要把短训练未收敛当作路线无效。

pi_avoid仍输出帆舵控制，不是另一个全局规划器。它应兼顾目标推进和安全，奖励沿用并适配原任务，重点包括真正安全违反、到达/进展、时间和合理操纵代价；不要求每一步都靠近目标，不把“目标出视野”作为避让成功奖励。

### 5.3 接管状态与交还训练

避免只在静止且正对目标的理想初态训练。复用pi_nav实际rollout前缀或完整初始化后航行一段，采集不同速度、航向、帆舵和风况下的接管状态。

先训练pi_avoid在这些状态下完成安全推进，再测试交还pi_nav后的完整任务。可用简单课程学习逐步增加近距离、转向和静态障碍，不建设复杂课程调度系统。

若加载已有快照，必须恢复与物理执行一致的必要状态。pi_nav和pi_avoid参数不同，不能直接把前者LSTM状态复制给后者当作正确记忆。

### 5.4 策略切换接口

第一版硬切换：每个控制步只执行一个Actor输出，二者共用原动作单位、量化、执行器设定值与限幅。不平均两个命令；切换不重置物理状态、不清零帆舵、不重启任务时钟。

对非活动策略，优先持续用真实观测更新各自记忆，仅不执行其输出；若原代码更适合接管前的历史重放，可用更简单且正确的一种。实际前向次数必须一致，不能同一时刻多更新一次记忆。动作历史只能写本船实际执行的命令，不能写未选Actor的假想动作。

沿用当前真实控制步顺序，说明路由决定作用于本步还是下一步；不要为了包装延迟效果另造时序。记录基本单步耗时即可，不增加复杂异步服务。

## 6. 路由：先有最小闭环，再检验风险判断的额外作用

先实现能够切换和恢复的简单范围路由，作为工作基线；它不是预先指定的论文主方法。

- 有当前可见目标或仍在短时保护内的目标时，由pi_avoid接管。
- 无相关目标且保持/保护条件结束时，交还pi_nav；不能只因某一帧目标出视场就立刻退出。

pi_avoid有足够基本能力后，再实现一个轻量风险路由：

- 对可见或有效短时缓存目标，根据相对位置和相对速度计算有限时间的预计接近。
- 时间窗可从30 s起步，接近阈值依据既定安全距离、船体响应和少量开发数据取值，不直接继承A的30 m guard。
- 关注同一时刻的间距，不用“几何航线相交”作为唯一条件；追越也可能危险，错时横穿也可能安全。
- 采用少量进入/退出迟滞或短保持，避免每秒切换。5 s保持/持续判断仅作为可调起点，不同时扫一堆门槛。
- 退出需要风险下降及合理接回条件；考虑恢复正常目标后是否再次朝冲突区域靠近。先用简单方向/接近几何，不调用A线昂贵的S15候选预测。
- 从当前真实位置更新前方局部参考、接回任务，避免返回已经经过的航迹点；不必每次都全局重规划。

两种路由使用同一动态专家权重和合法观测，分别在自己的真实轨迹上决策。不要复制另一方法的未来触发时间。

本轮不训练第三个路由网络，不做复杂MoE系统。若规则路由的确成为主要瓶颈，先提交真实例证和一个改进方向，不自动把项目扩成另一项训练任务。

4. 双策略＋轻量风险/交还路由。

关键区别：第1对第2回答新动态策略是否学到能力；第2对第3/4回答路由是否值得；第3对第4回答风险判断与交还是否有额外作用。

用方法选定后的约20—30个新场景做第一批小确认，包含冲突、无冲突、前向边界丢失/再见及少量静态混合。具体数量在看结果前按成本固定，不机械要求几百场。所有方法使用同场景同外生过程，保留所有失败。

报告安全完成与到达分开、最小实际间距、任务航时和航程、接管时长/切换次数及实际计算代价。航时用明确共同安全子集，不把失败提前停止当快到达，不让不可见目标从判分中消失。

若pi_avoid尚未学会基本避障，优先修训练并说明当前不足，不堆路由阈值来掩盖。若一直使用pi_avoid已经最好，接受“当前路由无明显必要性”；若范围路由够用，不强行选择更复杂的版本。

### 第四步：输出能看懂的实际过程

至少保存几段真实完整航迹：一次正常通过、一次实际避让并交还、一次失败或明显代价。标出两船同步时间、当前FOV、策略接管区间和实际最小距离。优先用已有二维绘图/动画脚本输出短MP4或GIF；不为视频新建渲染引擎，也不用生成式图像冒充实验。

最终结论按“背景—具体问题—采用的方法—训练实际做了什么—效果—代价与限制”组织，不以测试数量、文档数量、模拟Accept或成功个例代替结论。
