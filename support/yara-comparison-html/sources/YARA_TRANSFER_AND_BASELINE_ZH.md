# 师兄方法迁移到 Yara：接口核验与复现建议

核验日期：2026-11-06。结论：可以迁移研究方法并重新训练，但不能把现有权重直接连接 Yara 的 5D/3D 接口。建议先做无障碍航点任务，迁移循环 SAC 的历史利用方式，重新初始化策略；旧权重微调作为次级对照。尚未开始训练，也没有证据证明迁移优于原版 PPO。

## 2. 观测、动作与时序：逐项对照

| 项目 | 师兄当前14D接口 | Yara Eboat53-v0 | 迁移含义 |
|---|---|---|---|
| 观测 | x,y,横滚φ,航向ψ,纵向速度u,横向速度v,横滚/偏航角速度p,r,帆角,舵角,距离进展,横向坐标差进展,目标x,y | 距目标d、相对目标角β、u、视风速、视风角 | 非同一观测；不能补零后称等价 |
| 风信息 | 无直接风观测 | 两项直接视风观测 | 无风方案须与同信息的MLP/历史基线比较；原版有风PPO另列参考 |
| 单位/归一化 | 位置m、角度rad，保存的Z-score统计 | d→2d/120−1；β→β/180；u→u/10；视风速→w/15−1；视风角→角/180 | 旧归一化器不能默认沿用；新训练统计仅来自训练集 |
| 输出 | 两个归一化动作经adapter变为约±10°增量 | 3个[-1,1]动作 | 输出数和语义均不同 |
| 帆执行 | 有符号目标帆角累加，约束±90°，再受速率限制 | `(a0+1)*45°`控制帆缆放开范围0–90°，由风推动帆在范围内转动 | **Yara不是直接控制有符号帆角**，取绝对值不能保证等价 |
| 舵执行 | 增量累加，最终限幅±30° | `60*a1`度绝对目标 | 需选择统一接口，不能把增量当绝对角 |
| 电机 | 无 | `int(5*a2)`，向零截断为−5…5档 | 纯帆任务要对所有比较方法统一禁用并重训，不能只禁用原版模型后宣称它差 |
| 步进 | 一步积分1 s | 解暂停→发布动作→等下一条观测→暂停 | 插件frequency=2实际表现为约2 s周期，非2 Hz；实测有墙钟/通信造成的细小差异 |
| 记忆 | 当前状态另一路，历史状态+历史动作经LSTM；训练序列10步 | 原版5D网络为无记忆MLP | 原10步约10 s，移到Yara约20 s；需要记录物理时间而非盲保窗口长度 |

18D资产在上述14D基础上增加两个障碍距离/方位对，并使用注意力。它与期刊14D控制器不是同一个checkpoint。当前无障碍迁移没有必要默认携带这四维及注意力。

原环境动作实现还包含按1°向下取整、累积目标和执行速率限制。迁移应明确选择“复用其研究结构”还是“复现其全部动作细节”，不能悄悄改变后继续使用原成绩。世界坐标速度必须旋转到船体系；角度方向、度/弧度、视风去向与气象来向须用固定状态/单舵脉冲核对。

原师兄环境参数包含25900 kg船体质量；Yara用E-Boat模型的多个刚体及Gazebo动力学。仅此也足以说明旧策略作用对象发生显著变化，不能把网络形状匹配解释为行为可迁移。

## 3. 奖励与任务口径

当前Yara代码定义Δd=d_previous−d_current，e=min(|实际电机档位|,5)，Dmax=120 m：

```text
d < 5.1 m:       r = 1
d > 120 m:       r = -1
Δd > 0:         r = (Δd/120) * (1 - 0.9 e/5)
其他:            r = 2 Δd/120 - 0.01 e
```

到达、超距或NaN触发terminated；step_count>300触发truncated（首次在第302次step检查时成立）。距离由三维位置距离计算，图中的水平圆只是展示。

师兄14D奖励包括`2*距离进展 + x坐标绝对差进展 + 0.5*u/(1+abs(v))`，叠加动作惩罚、缩放、375/250/125 m里程碑奖励、10 m到达奖励40、截断惩罚100及每步−0.2。直接搬到100 m任务会使里程碑立即触发，且单位/尺度/时长都改变。因此首轮匹配比较建议保留同一Yara奖励，不同时改奖励与网络。

## 4. “原版Yara”必须分成两个口径

**当前仓库复现**：保留本次固定commit及其环境，用仓库权重或显式训练配置。已经通过接口探测；尚未完成完整评估或重新训练。

**论文协议复现**：论文第5.2节/算法2给出100 m任务、5D/3动作、随机风与初始航向、500k训练步。论文Dmax=1.25D0、到达<5 m、后退项没有代码中的系数2；当前代码是1.2D0、5.1 m、后退×2。论文连续均匀采样风，当前环境采用离散风速/方向，reset未执行论文所述航向随机化。两者不能混写成精确复现。

原文七航点演示中SAC弱于PPO/PID；不能据此把所有Yara模型概括为差。原文自身将这组实验定位为环境应用展示。正式对照应保留PPO和合理简单控制器。[论文原文](https://link.springer.com/content/pdf/10.1007/s10846-024-02212-1.pdf)

## 5. 推荐的迁移路线（尚未实施）

第一步复用师兄14D的循环SAC结构及序列采样思想，**在Yara重新训练**，不优先移植18D避障模块。建议因果观测从目标相对几何、船体运动、实际执行器状态构成；不把风向、未来状态或相机真值作为无风策略输入。可从11维开始：距离、目标角sin/cos、u/v、横滚φ、p/r、帆缆放开范围、实际帆角、实际舵角。Gazebo真值接口只是第一阶段理想传感器代理；需显式说明无噪声假设，后续再加入对应传感器噪声。

```text
GPS/姿态/速度/执行器反馈（仅当前及过去）
          ↓ 坐标与单位转换、训练集归一化
当前观测 ───────────────┐
历史观测+历史实际指令 → LSTM → SAC策略
                       ↓
           帆缆放开范围 + 舵目标
                       ↓
           Yara执行器与Gazebo动力学
                       └→ 下一次实际反馈
```

动作先采用Yara原生的帆缆范围和绝对舵角，避免把旧有符号帆角强行等价映射。纯帆版本的所有匹配方法统一电机为0，并从头训练；有电机的原版5D PPO/SAC保留为原论文条件的独立参考，不能把两种任务的成功率混成一张排名。

核心比较先做：同无风输入MLP-SAC、同输入历史堆叠MLP-SAC、循环SAC；保留原版有风PPO作为信息更充分的参考。若要隔离记忆收益，帆舵接口、奖励、风分布、训练步数和评估实例必须相同，网络容量差异记录清楚。之后再考虑“循环骨干warm start vs从头训练”，旧输入/输出头、归一化、critic和replay不默认继承。

先测无GUI的1000步吞吐和动作生效时序，再定训练墙钟预算。现有基准smoke使用约实时的physics max_update_rate；原训练helper会将其设为0加速，但当前step在发布动作前解暂停，提速后通信延迟可能改变动作落地时间，必须先测，不能把同一步数当完全相同物理协议。本轮未启动吞吐实验或训练。

开发阶段建议按共同固定风/航向集合验证100 m任务，再验证连续多航点；冻结确认实例在方案确定后只评估一次。报告到达率、超时/超距、航时、航程、操纵量和电机使用，不能只看reward。建议以每方法500k步为最初预算量级，至少多个预定seed确认；具体资源授权和实测速率确定后再启动。少量pilot失败不能判定循环方法无效。
